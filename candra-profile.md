## 4. How I like to work
- Quick questions get short answers. "Yes or no only" means exactly that.
- I think out loud and iterate in small steps. Several rounds of tweaks are normal.
- I react fast to friction: "too complicated", "inconvenient". Simplicity beats coverage.
- I test on real devices and paste back screenshots and console errors.
- Both are true: I like animation and fun movement, and I do not want it overblown.

## 5. Build rules
- Preferred form: a single `.html` file, opened by double-click.
- Avoid: API keys, accounts, localhost servers, install or setup scripts, CDN-only dependencies that fail offline.
- Large builds: confirm scope first. Test before delivering. Say what was not tested.
- Repos: GitHub is read-only for Claude. I apply changes by hand.
